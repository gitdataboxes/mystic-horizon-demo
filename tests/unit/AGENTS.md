# tests/unit/ — Unit Suites

## Purpose

Focused unit tests for isolated Python modules with narrow doubles and explicit dependency injection.

## Ownership

- Shared

## Conventions

- Mock at module boundaries.
- Keep assertions scoped to one behavior where possible.
- Runtime-service tests should cover rollback and shutdown ordering, not just happy paths.
- Runtime-service tests cover local-mode startup (no Twilio), verify bridge and phone reconcile task draining on shutdown, test `start_full` (no separate bootstrap mode, FAQ indexing moved to background task — not in startup steps, phone readiness checked after the server starts when Twilio is configured), and `start_runtime_from_setup` (progress hooks, `before_server` callback, DB kept open on start failure).
- CLI and multi-agent tests should keep using temp filesystem fixtures instead of global state.
- Agent worker entrypoint tests should fake `JobContext` and `AgentSession` event callbacks instead of booting a real worker. `_SessionStub` includes `interrupt`, `generate_reply` (records kwargs for assertion), `history` (`_HistoryStub`), `current_agent` (`_CurrentAgentStub`), and `output`/`input` (`_AudioToggleStub` with `set_audio_enabled` for voice control tests). Room mock captures `on` event handlers via `_event_handlers` dict for data-channel test dispatch. Helpers: `_fire_data_channel_chat` triggers the `data_received` handler with optional `clientMessageId`, `_fire_data_channel_packet` triggers generic data channel packets (e.g., heartbeat `mh.ping`), `_fire_voice_control` triggers the `mh.voice_control` data channel handler with a start/stop action, `_fire_conversation_item` triggers the `conversation_item_added` handler to simulate agent responses, `_published_agent_events` extracts published events from `publish_data` calls.
- Agent tools tests verify direct per-skill tool exposure, raw-arguments invocation (`raw_arguments={"type": ..., ...}`), owner/public filtering, and modality filtering. Missing `type` arguments return error strings instead of crashing. 48 skills in registry, including `read-twilio-numbers`.
- Phone readiness tests (`test_phone.py`) isolate `mystic.phone.ensure_phone_line_ready()` with mocked Tailscale/Twilio transports; cover ready state, webhook repair, inspect-mode mismatch without mutation, and Tailscale-down offline reporting.
- Interaction vocabulary tests (`test_interactions.py`) verify `describe_interaction` for dashboard/phone channels with text/voice modalities, `describe_call` from dataclass-like objects, `format_interaction_brief` (e.g., "Outbound phone call", "Dashboard chat").
- LiveKit server/preflight tests should assert actionable install guidance, version validation, and binary resolution order without shelling out to real package managers. Server start tests verify explicit `--rtc.tcp_port` and `--udp-port` flags derived from the HTTP port. `FakeProcess` provides `stdout` (BytesIO) and `stderr=None` to match merged output capture.
- `RoomMetadata` tests cover `attentionCue`, `noResponseTimeout` parsing, rejection of non-positive timeout values, `bootstrap` field parsing (with and without `firstMessage`, defaults to `False`), and `kind` parsing (defaults to `"dashboard"`, accepts `"game"`, coerces unknown values back to `"dashboard"`).
- Game-room endpoint tests (`test_web.py`): `POST /dashboard/api/game/token` requires auth, calls `_create_dashboard_room_with_agent_dispatch` with `metadata["kind"] == "game"` (no `callId`), and returns a `game-*` room name + `pilot-*` participant name; repeated requests produce unique rooms. `GET /dashboard/api/game/scores` returns the leaderboard rows written via `insert_game_score`, ordered by score desc.
- Belter Copilot persona + tools tests (`test_game.py`, 33 tests): `ALARM_EVENTS` is the full speak-event whitelist — core alarms (`system_boot`, `shield_online`, `shield_refused`, `shield_depleted`, `shift_jump_refused`, `force_field_refused`, `lightning_weapon_refused`, `voice_weapon_refused`, `hull_lost`, `ship_destroyed`, `game_over`) plus flow cues (`wave_cleared`, `kill_streak`, `near_miss`, `high_score`, `wave_stalled`, `idle`). Only `game_tick` is silent (state cache updates only). `format_game_event_cue` produces neutral `[EVENT_TYPE] key=value` telemetry lines: uppercase bracketed event type, whitelisted keys emitted in `_CUE_KEY_ORDER` (`wave`/`next_wave`/`score`/`lives_remaining`/`waves`/`count`/`reason`/`unlock_wave`/`rank`/`prev_best`), unknown payload keys are dropped, `beat_names` special-cased as `ghosts=A,B,C` (uppercased, blanks dropped, capped at 3), empty event type returns `""`. `GameState` defaults (wave=1, shot_pattern="single", shield "available", lightning/voice weapon status strings that branch on unlock wave and cooldown ms), `arm_shield`/`bump_cooldown` transitions, `apply_game_tick` merging including `force_field_active`/`lightning_cooldown_ms`/`voice_weapon_cooldown_ms` (ignores invalid shot patterns + non-numeric values, clamps negatives to 0), `format_ship_status` one-line summary covering wave/lives/score/field/shield/force-field/lightning/voice-weapon/pattern. `parse_game_packet` happy path, missing-payload default, and rejection of invalid bytes/arrays/empty-type. `build_game_tools()` returns exactly `{enable_shield, engage_shift_jump, enable_force_field, fire_lightning_weapon, fire_voice_weapon, change_shot_pattern, read_ship_status}`. Invariants: `VALID_SHOT_PATTERNS == ("single","spread","rapid")`, `SHIELD_MAX_PARTICLES == 10` (matches graph person-node atomic orbit: 5 shells × 2 motes), `LIGHTNING_UNLOCK_WAVE == 1`, `VOICE_WEAPON_UNLOCK_WAVE == 2`.
- Mock targets use flat module paths (e.g., `mystic.config.some_fn`, not `mystic.core.config.some_fn`). After the module split, mock HTTP/tunnel targets at `mystic.http`, audio targets at `mystic.audio`, and worker targets at `mystic.worker`.
- Test files use descriptive names — phase-numbered suffixes have been removed (e.g., `test_voice_pipeline.py`, not `test_agent_phase10.py`).
